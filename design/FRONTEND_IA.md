# 前端第一阶段信息架构

日期：2026-09-29；范围：App Shell、Home、Vault、Job。该文档规定内容层级与使用路径；具体视觉细节由 Cursor 在现有技术约定内实现，当前不代表视觉稿已验收。

## 全局结构

桌面采用稳定导航、当前目标选择和主内容区；窄屏改为紧凑导航，详情可独立占据主内容区。所有页面持续显示“演示数据”标记，并说明保存位置为当前浏览器本地，不能使用“已同步云端”。

主导航只包含当前可用的三个入口：

| 展示名 | 职责 | 主要下一步 |
| --- | --- | --- |
| 求职首页 | 看当前目标进展与待办 | 打开关联岗位或资产 |
| 职业资产 | 查看和维护可追溯的经历证据 | 核对来源、编辑资产、返回岗位 |
| 岗位工作区 | 判断具体岗位与现有证据的关系 | 查看证据、准备投递 |

求职目标使用全局选择器，本阶段不增加独立目标编辑页。文档、投递看板和面试工作区不作为可用导航展示；文档仅从明确的“准备投递”操作进入占位。

目标切换是当前浏览上下文变化：Home 和 Job 按目标过滤；Vault 保持该用户共用资产。关联岗位的返回路径必须携带目标和岗位 ID，不从当前选中公司名推断。

## Home：先看下一步，再看进展

内容顺序：当前目标及简短说明 → 四项指标 → 待办 → 相关岗位入口。

- 指标固定为已分析岗位、已投递、HR 回复、面试次数，口径以 Schema 为准。
- 待办展示动作、关联岗位／公司、明确的时间（有时间时）及状态；面试排期不等于已完成面试次数。
- 主要操作为“查看岗位”或“查看资产”等实际可执行动作。第二轮面试准备尚未开放时，进入关联岗位并说明当前可用范围。
- 无待办时展示“当前目标暂无待办”及岗位入口；不凭空生成“AI 建议”。
- 不提供无实现支撑的一键优化、智能规划或进度百分比。

## Vault：证据、来源、确认分开呈现

内容顺序：资产列表／筛选 → 当前资产详情 → 来源及确认状态 → 相关操作。

每条资产展示标题、类型或简要内容、当前 revision、来源及确认状态。不要将“有来源”显示成“用户已确认”，也不要将编辑保存当作真实性确认。

详情可查看当前资产内容与原始来源摘要；来源缺失或未确认时明确说明。由岗位证据进入时突出对应资产，并保留“返回某岗位”入口。

编辑使用明确的编辑状态：

1. “编辑资产”打开草稿，提供标题、正文输入和默认不选的“确认这次修改”；标题／正文改变时，未选也可保存，但新版本为待确认。
2. “保存修改”为主要操作，“取消”为次要操作。
3. 校验错误靠近对应输入；保存失败保留草稿并展示原因。
4. 保存成功显示本地保存结果；引用旧 revision 的评估显示需要更新。仅确认待确认资产按契约保存；内容无变化且无新增确认时保留原确认状态，不制造一次更新。
5. 草稿离开保护覆盖页面导航和目标切换，浏览器关闭／刷新使用标准保护。

本阶段不新增资产上传、删除、合并或批量确认入口。

## Job：判断必须能回到证据

内容顺序：当前目标岗位列表 → 岗位基础信息 → Match／Gap／Evidence／Risk → 主要操作。

| 区域 | 内容 | 交互边界 |
| --- | --- | --- |
| 岗位列表 | 岗位、公司、地点或必要摘要、已有记录提示 | 按 `goalIds` 过滤，使用 Job ID 打开详情 |
| 岗位信息 | 岗位要求和来源、所属当前目标 | 不把缺失薪资／要求补成确定事实 |
| Match 匹配项 | 与要求有关的现有能力及简短依据 | 每个有引用的判断可定位职业资产 |
| Gap 缺口 | 目前缺少的经历或证据 | 用“缺少证据”等准确表述，不推断用户一定不会 |
| Evidence 证据 | 资产名称、摘要、引用 revision 与评估时快照 | 可对照原证据及当前资产；打开资产并可返回；旧 revision 显示过期提醒 |
| Risk 风险 | 与岗位判断有关的不确定项 | 与事实区分，展示为演示判断 |

预置评估持续标记“演示评估”。资产修改后，保留旧评估并说明“引用的职业资产已更新，当前评估可能过期”；本阶段不提供会伪装成真实重新分析的按钮。

主要操作为“准备投递”；相关操作为“查看职业证据”。已存在的投递或面试信息只读呈现，不把准备材料混同为已投递。

## 文档占位：完整传递上下文

展示当前目标、岗位与公司，标题为“准备投递材料”，说明“文档工作区将在下一阶段开放”。提供“返回岗位”，恢复进入时的目标与岗位。

此页面不展示生成成功、导出成功或投递成功，不创建文档、Application 或业务事件。未知岗位或目标组合不可继续展示，应提供可恢复错误提示。

## 共用交互要求

- 加载、空、失败三种状态必须区分。失败提供可执行重试或恢复入口；不把错误藏成空列表。
- 保存、重置等操作在进行中避免重复提交。保存是否成功以数据层返回结果为准。
- “重置演示”放在次要位置；确认时说明将清除本地演示修改。取消不改变数据。
- 启动存储不可用时展示“本地保存不可用，当前仅供浏览”，禁用保存和重置；目标临时切换不承诺刷新保留。正常模式运行中写失败则保留草稿与旧状态，不自动降级。
- 存储损坏时保留原串，提供只读预览；恢复正常使用所需的重置必须明确确认且写入成功。
- 故障注入仅用于隔离测试或控制台辅助，不把技术场景选择器加入用户流程。
- 用户输入通过安全文本方式渲染；表单、可点击元素、提示消息采用合适的语义和键盘行为。
- 所有主要动作有文字标签；图标加载失败不能导致操作不可识别。
- 正常视图避免堆积功能卡片、过多口号或将四项指标包装成复杂图表。用内容层级呈现任务与证据。

## 视觉实现边界

以清楚、平静的工作台为方向：单一主要强调色、足够对比度、统一间距与字体层级、可读的中文文本、可见键盘焦点。优先保证约 1440px 桌面与约 390px 窄屏的操作路径，不为本阶段额外制作营销首页或品牌系统。

尚无已验收视觉方向时，先完成一致且可用的一版；交接记录截图及反馈。若用户后续确认某一方向，局部迭代需保留已验收的结构，不自行重设计。
