# Career Agent｜第二阶段施工任务包

状态：ready_for_cursor
负责人：Cursor 实现；Codex 负责契约复核与关键节点 Review。

## 目标

在第一阶段求职进展、职业资产和岗位工作区稳定的基础上，补齐最小可演示的文档工作区、投递材料版本和面试记录／复盘入口。继续使用统一合成数据集、本地浏览器保存和现有业务操作入口。

## 本阶段范围

1. **文档工作区**
   - 从岗位详情进入“准备投递材料”。
   - 支持基础简历、定制简历、自我介绍、开场沟通四类材料的演示编辑；面试准备材料在面试记录建立后进入。
   - 每次保存生成不可覆盖的材料版本；投递记录引用具体版本。
   - 未接入真实 AI、上传、外部平台或自动投递。

2. **投递跟进**
   - 区分“准备投递”和“已记录投递”。
   - 支持记录投递时间、渠道、招聘方回复状态和备注。
   - 不把未知回复显示为已回复。

3. **面试记录与复盘**
   - 从岗位详情进入面试记录列表。
   - 支持多轮面试，按面试 ID 关联岗位和投递记录。
   - 支持记录面试时间、轮次、状态、用户笔记和复盘结论。
   - 对预置分析明确标注“演示预置”；新输入只保存为“尚未分析”。

4. **求职进展二级页**
   - 保留已分析岗位、已投递、招聘方回复、面试次数四个入口。
   - 二级页显示当前目标下的岗位／投递／面试记录，并可返回原上下文。

## 不在本阶段

- 真实 AI 调用、模型密钥、云端账号和同步。
- 自动投递、外部招聘平台连接、真实文件上传。
- 通用 Agent 编排、消息队列和跨设备协作。
- 修改现有事实确认规则、状态枚举或历史快照语义。

## Codex 契约复审结论（2026-09-29）

- 现有 `DATA_SCHEMA` 已定义 Document／DocumentVersion、Application 材料版本引用和 Interview 字段；现有 `STATE_EVENT_MODEL` 已定义投递、回复、多轮面试、面试完成、文档版本保存事件。
- 本任务包按现有契约收窄文档种类，不新增状态枚举，不改变历史快照语义，不允许 DocumentVersion 原地覆盖。
- 面试复盘字段使用现有 Interview 的 `transcript` 与 `review`；新输入保存后标记为“尚未分析”，不得伪装为模型结论。
- Application 与 Interview 只通过 ID 关联；目标和岗位从 Application 读取，禁止按公司名称猜关联。
- 结论：契约范围可施工，状态改为 `ready_for_cursor`。如实现中发现字段或事件不足，先在 `docs/HANDOFF.md` 记录问题和最小建议，暂停相关扩展。
