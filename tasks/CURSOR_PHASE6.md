# Career Agent｜第六阶段任务包：真实 AI 建议接入准备

状态：accepted
日期：2026-09-30
前置：第五阶段已 accepted

## 目标
为“帮我改简历”接入真实 AI 建议建立可控边界。实现模型调用前的产品流程、提示词预览、隐私说明、失败处理和结果确认；只有在明确配置模型提供方和密钥后才允许真实调用，未配置时必须显示“尚未接入真实 AI”，不能用固定文案冒充生成结果。

## 必须完成

1. 将岗位定向修改拆成清晰的三步：准备内容、生成建议、检查并保存。
2. 在生成前展示发送范围：目标岗位信息、用户主动确认的简历正文；明确说明当前是否会发送到外部模型服务。
3. 增加模型提供方适配边界（provider adapter），页面不得直接散落 API 调用；未配置 provider 时显示可理解的不可用状态。
4. 固定提示词模板必须要求：只基于简历原文和岗位信息；不得编造经历、公司、数字或技能；输出结构化建议并引用原文段落；无法判断时标记“需要用户确认”。
5. 真实调用失败、超时、限额或返回格式错误时：保留原简历和当前草稿，显示原因与重试入口，不写入成功结果。
6. 生成结果进入现有逐条处理界面，支持采纳、跳过、改写后采纳；采纳前不修改原简历，保存后创建岗位新草稿。
7. 记录本次生成的时间、岗位上下文、模型提供方和结果状态；不得记录密钥，不得把简历正文写入日志。
8. 在页面明确标注：真实 AI 生成需要配置服务和费用；当前演示环境若未配置则不能生成。
9. 不修改既有 ResumeFile、DocumentVersion、确认状态和事件语义。若必须新增字段或事件，先在 HANDOFF 写“问题、影响、最小建议”，暂停该部分实现。

## 不在本阶段

- 自动投递；
- 自动覆盖简历；
- 后台长期保存完整提示词和完整简历正文；
- 多模型路由、复杂 Agent 编排、自由聊天；
- 未经配置直接连接任何外部服务；
- 用固定演示建议伪装真实模型结果。

## 验收重点

- 未配置模型时页面不会显示“生成成功”；
- 用户能知道哪些信息会被发送以及为什么；
- 真实调用失败不覆盖旧内容；
- 返回结果必须能指向原文并进入现有逐条处理流程；
- 采纳、保存、确认的时机保持不变；
- 密钥不出现在页面、localStorage、事件和日志中；
- 逻辑和浏览器测试覆盖未配置、失败、重试、成功后的草稿保存；
- 完成后更新 HANDOFF 为 `ready_for_review`，如真实 provider 未配置要明确写“未验证真实调用”。
