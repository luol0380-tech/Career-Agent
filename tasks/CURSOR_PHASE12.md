# Career Agent｜第十二阶段任务包：后端接入 DeepSeek（真实简历修改）

## 目标

用本机后端读取 `.env` 中的 `DEEPSEEK_API_KEY`，代理 DeepSeek 调用；前端提交简历正文与岗位要求，返回可采纳的结构化修改建议。失败保留原稿并支持重试；不得编造经历或成果；密钥不得出现在前端、仓库、日志、截图或聊天中。

## 与既有实现的关系

- 复用：`app/lib/revise-prompt.js`（系统提示、用户消息、JSON 解析与原文引用校验）、`#/resume/revise` 三步流程、本地演示建议路径。
- 替换主路径：浏览器直连 DeepSeek／页面粘贴 API Key（第七阶段会话配置）→ **默认改为调用本机后端代理**。
- 会话内粘贴 Key：可保留为降级／调试选项，但正式验收路径以服务端 `.env` 为准；前端不得把密钥写入业务 localStorage。

## 必须完成（实现阶段，待 Codex accepted 本任务包与 HANDOFF 接口草案）

1. 新增最小本机后端（建议 Node 原生 `http`，不引入构建链）：从项目根 `.env` 读取 `DEEPSEEK_API_KEY`（可选 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`）；密钥仅进程内存。
2. 提供 HTTP 接口（见 HANDOFF 接口草案）：状态查询、连接验证（短探测、不发简历）、生成建议（简历＋岗位）。
3. 服务端调用 DeepSeek `https://api.deepseek.com/chat/completions`（默认模型 `deepseek-chat`）；响应经与前端一致的结构校验；不合规则返回失败，不伪造成功。
4. 前端 `ai-provider`：优先走后端代理；展示「后端已配置／未配置／请求中／成功／失败」；发送范围二次确认仍保留。
5. 失败：保留原 `ResumeFile.textDraft` 与当前岗位草稿；可重试；用户可读错误（超时、限额、权限、格式、后端未启动／未配置）。
6. 成功：进入既有逐条采纳／跳过／改写／保存新草稿流程。
7. 本地演示建议路径保留，明确非真实 AI。
8. 提供 `.env.example`（无真实密钥）；确保 `.gitignore` 忽略 `.env`。
9. 测试：逻辑／契约校验不外呼；后端可用 mock 覆盖成功／失败；无真实 Key 时不得写「真实调用通过」。
10. **未经用户明确要求，不启动、不停止项目服务**；实现可写代码，启动指令只写在交付说明中待授权。

## 安全底线

- 不输出、不打印、不提交 `DEEPSEEK_API_KEY`。
- 服务端日志只记时间、状态码、建议条数、错误码；不含密钥与简历全文。
- 前端安全日志同第七阶段规则。

## 验收重点（实现后）

- 本机配置 `.env` 且用户授权启动服务后，改简历页可真实生成建议并进入采纳流程；
- 无 Key／服务未开时不伪装成功；
- 失败可重试且原稿不变；
- 密钥不进前端存储与仓库。

## Codex 已确定的实现边界（2026-10-09）

- 同一 Node 进程托管 app 静态资源和 API，前端使用同源相对路径；服务只监听 127.0.0.1。
- 正常产品入口移除浏览器粘贴密钥与直连模型路径；测试适配器可以保留，不能让代理失败后静默转为直连或演示成功。
- 静态文件采用目录白名单，仅暴露 app 所需资源；禁止暴露项目根、.env、.git、docs，防止路径穿越。
- POST 校验同源 Origin／Host、Content-Type、字段类型和长度；请求体上限 256 KiB，外呼超时 60 秒，禁止无限重试。
- 状态查询不外呼；连接验证和生成仅由用户点击触发。上游错误不透传原始响应或正文。
- 模型响应的原文引用校验不能证明内容没有编造；页面必须提醒检查新增事实，结果经用户选择和确认后才保存。
- 不新增业务事件；第十一阶段冻结。实现交付后独立审核，真实调用仍待明确启动授权。
