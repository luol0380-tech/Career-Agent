## 当前范围

| 模块 | 本阶段完成 | 边界 |
| --- | --- | --- |
| App Shell | 三页导航、当前目标选择、演示标记、路由恢复、全局反馈、重置入口 | 不做账号登录或云同步 |
| Home | 当前目标的四项指标、待办列表、相关岗位入口 | 所有数字从统一数据计算，不做独立 Insights |
| Vault | 职业资产列表、详情、来源与确认状态、编辑／取消／保存 | 不做上传解析、新增资产、删除资产或自动确认 |
| Job | 当前目标岗位列表、详情、Match／Gap／Evidence／Risk、证据定位 | 评估为预置演示；不调用模型，不实时重新分析 |
| 文档占位 | 展示已传入的目标及岗位、明确说明后续阶段、返回原岗位 | 不生成文档、不保存文档、不创建 Application |

**最小业务写操作只有三类：职业资产编辑、当前目标选择、演示重置。** 职业资产编辑可按契约产生对应事件；路由、筛选、编辑草稿等界面状态不伪装成业务事件。Application、Interview、ActionItem 仅作为统一数据中的只读记录参与首页及岗位展示。

本阶段不实现 Document、DocumentVersion、TaskRun，不实现真实 Agent、通用状态机、自由文本意图识别、真实文件解析、自动投递、真实数据库、账号系统或部署。状态与事件只采用已有契约允许的部分，不复制一套到页面。

## 技术与目录

- HTML、原生 JavaScript、Tailwind CDN、Font Awesome；不引入框架或 npm 构建链。
- 入口为 `app/index.html`，可直接以文件方式打开。使用普通 `defer` 脚本及显式命名空间，不依赖 `file://` 下的 `fetch`、ES Module 或模块打包。
- CDN 地址遵循 AGENTS；基础可读样式由本地 `styles.css` 提供，外部资源失败时给出可见提示。
- 按 `domain/`、`data/`、`fixtures/`、`features/`、`components/` 分离职责。小模块可以合并文件，但不能把全部视图、持久化和业务规则写进一个脚本。
- 页面只调用统一异步数据接口；存储、校验、revision 更新和指标计算不散落到视图。
- 不启动、不停止项目服务。不初始化远端、不 commit、不推送、不部署。

建议通过 hash 路由支持直接打开文件、刷新和浏览器前进／后退；具体参数命名由实现者选择，实体关联始终使用 ID。坏路由或缺失 ID 显示可恢复状态并提供回到首页的入口，不能静默打开另一个岗位。

## 统一演示数据

至少包含 1 个合成用户、2 个目标、3 个岗位、足够解释评估的职业资产及来源。所有实体、关系和状态值以 Schema 与状态事件契约为准。

| 数据场景 | 约定 |
| --- | --- |
| 目标一 | `goal_ai_pm`；岗位 `job_001`、`job_002` 的 `goalIds` 包含此目标 |
| 目标二 | `goal_b2b_pm`；岗位 `job_003` 的 `goalIds` 包含此目标 |
| `app_001` | 关联目标一与 `job_001`，处于准备阶段，尚未记录已投递 |
| `app_002` | 关联目标一与 `job_002`，已投递且处于面试阶段；第一轮已完成，第二轮已排期 |
| `app_003` | 关联目标二与 `job_003`，已记录投递，尚无 HR 回复和已完成面试 |
| 目标一指标 | 已分析岗位 2、已投递 1、HR 回复 1、面试次数 1 |
| 目标二指标 | 已分析岗位 1、已投递 1、HR 回复 0、面试次数 0 |

面试次数只计已完成面试；第二轮排期作为待办展示，不提前计为完成次数。指标严格使用契约计算：不能把事件条数、评估版本数或准备中的 Application 当成对应指标数量。

Job 的 `goalIds` 表示岗位收藏／归属范围；Application 的 `goalId` 表示该次投递所属目标，两者职责独立。切换目标不能改写 Application、Interview、JobAssessment 或资产历史。职业资产是该用户的共用证据，不随目标切换被复制或删除。

至少准备 4 个职业资产（两个项目、一段经历、一项能力证据），其中至少一条可编辑且被评估引用、一条待确认；岗位评估包含缺口与风险。来源、用户确认和演示分析要能在页面上区分；不要用虚构准确率包装预置结果。合成日期明确标注“演示日程”，不随真实今天悄悄改写历史。

## 连续施工顺序

### 步骤 1：数据入口和应用骨架

建立统一 fixture、字段与引用校验、只读查询、允许的写操作以及带 `schemaVersion` 的持久化包。先建立路由、目标上下文和布局，再填充真实可点击的页面内容。

- 初次打开从 fixture 建立演示数据；后续读取已保存状态。
- fixture 保持不可变，每次初始化或重置使用独立副本。
- 写操作先校验候选状态，再尝试持久化；只有成功后才替换当前已提交状态并显示成功。
- 启动时探测到存储不可用，按 Schema 进入只读临时浏览，禁用业务保存及重置；目标选择只在当前 UI 临时生效，明确刷新不保留。不能用可写内存模式代替持久化。
- 正常模式运行中超额或写入失败时保留旧的已提交状态和编辑草稿，显示失败及重试入口，不自动降级，不能显示“已保存”。
- 存储损坏或版本不兼容时保留原始内容，不自动覆盖；提供只读初始演示预览和需要确认的重置入口。成功写入重置状态后才恢复正常模式。
- 存储键及快照结构直接采用 Schema。重置只处理本应用键；检测到其他标签页修改同键数据时暂停写入并提示重新加载，不宣称支持并发事务。

### 步骤 2：Home 与目标切换

从统一查询计算四项指标和待办。目标切换成功后同时更新岗位范围、待办和指标；刷新恢复已保存目标。目标选择的持久化失败时不假装切换已保存。

待办点击携带稳定 ID 进入当前已实现页面；尚未实现的面试准备等内容可打开关联岗位并解释当前阶段，不做无响应按钮。

### 步骤 3：Vault 与编辑

实现资产列表、详情、来源展示及 `title`／`body` 编辑。表单提供“确认这次修改”，默认不选；`confirmFacts` 按契约传递，标题或正文发生修改时，未选仍可保存且新版本为待确认。原始来源内容不因资产编辑而被改写；标题或正文修改后增加新的 manual_entry 来源，旧来源保留，编辑不等于自动确认。

保存有效改动时 revision 按契约递增，生成契约要求的记录。内容不变但显式确认已有待确认资产时，按契约递增 revision，不新建来源；内容不变且没有新增确认则不写入，也不撤销已有确认。命令带 `expectedRevision` 和 `commandId`；相同请求重试复用 commandId，数据层按契约生成 requestFingerprint 比较参数，过期 revision 或相同键不同参数拒绝覆盖。保存失败不递增已提交 revision；取消编辑不产生伪更新。已有评估保留原内容、原引用版本和 AssetSnapshot，通过版本差异标明过期，允许对照评估时证据与当前资产，不自动重算或覆盖。

用户带未保存草稿进行导航、目标切换、刷新或关闭时提供适当保护；取消离开应保留草稿和当前位置。刷新／关闭保护使用浏览器支持的标准机制，不依赖自定义提示文案一定显示。

### 步骤 4：Job 与跨页路径

完成岗位列表／详情及四类判断，证据引用显示资产名称和引用版本。点击证据定位对应资产，提供带岗位 ID 和目标 ID 的明确返回入口；浏览器返回同样可用。

“准备投递”进入文档占位并展示目标和岗位。占位页面必须说明“文档工作区将在下一阶段开放”，提供返回岗位的操作；此路径不得创建 Application、修改投递状态、改变四项指标或制造成功事件。

### 步骤 5：异常、适配与验收

补齐空数据、加载、读取失败、存储失败、未知路由和 CDN 失败状态。故障注入只放在测试入口或控制台辅助，不加入产品页面的场景选择器；不得修改正常 fixture 或破坏用户已有存储来制造故障。

完成桌面和窄屏检查，逐项记录 A01–A12。优先验证数据关系、保存结果、过期判定和业务边界；不为静态文案和简单样式新增一套测试框架。

## A01–A12 验收脚本

正常场景先使用初始演示数据；破坏性重置需界面确认，故障场景使用隔离存储或可控注入。每项记录实际操作、结果、验证方式与必要截图，未执行写“待验证／受阻”及原因。

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| A01 | 打开入口，依次访问 Home、Vault、Job；刷新详情；使用前进后退；访问不存在的路径和 ID | 三页互通；有效路由恢复；无效路径可恢复且不误关联其他对象 |
| A02 | 从目标一切到目标二，再切回并刷新 | 岗位、待办、四项指标同步过滤；目标持久化；目标二不显示目标一的排期待办 |
| A03 | 从岗位评估点击证据、定位资产，再返回岗位 | 定位正确资产；返回原目标与原岗位，不丢失上下文；无按公司名猜关联 |
| A04 | 修改一条已被评估引用的资产标题／正文并保存，分别验证未勾选／勾选确认，刷新后查看相关评估；另检查仅确认待确认资产 | 内容恢复；标题／正文修改时 revision 递增且新增输入来源；仅新增确认时 revision 递增、不新增来源；确认状态准确；旧评估内容、引用版本与证据快照不变，显示过期；无关评估不误标过期 |
| A05 | 记录操作前 Application 和指标；点击“准备投递”进入占位，再返回 | 占位的目标和岗位正确；Application、状态、指标和业务事件均无投递变化 |
| A06 | 修改资产后尝试离开；分别取消离开、放弃草稿；再直接取消编辑 | 取消离开保留草稿；放弃后旧内容不变；取消编辑不增加 revision、不写事件 |
| A07 | 用隔离验证场景展示无岗位／无待办、读取中、读取失败，再重试 | 状态可见且有合适解释；重试恢复；空状态不虚构内容；操作期间避免重复提交 |
| A08 | 分别模拟启动存储不可用、运行中写失败、损坏数据和其他标签页改动；尝试取消及确认重置 | 启动不可用只读且禁用保存／重置；损坏原串不自动覆盖；运行中失败的实体、来源、事件均不变且草稿保留；外部改动后暂停写入；可用存储下取消重置不变，确认后只恢复本应用演示 |
| A09 | 在约 1440px 桌面和约 390px 窄屏操作；仅键盘完成导航与编辑 | 内容可读，无关键内容被遮挡；按钮和输入可达；焦点可见；表单有标签；提示可被辅助技术感知 |
| A10 | 检查全局标记、来源、确认状态、预置评估及占位文案 | 合成 Demo 清晰；无虚假生成、上传、分析、云端保存或投递成功；未确认内容无事实化表达 |
| A11 | 检查正常操作控制台，再阻断样式／图标 CDN | 正常流程无未处理 JS 错误；CDN 失败时有提示，本地基础布局与操作仍可理解，图标不作为唯一操作标签；区分预期网络资源报错与应用 JS 错误 |
| A12 | 核对两组初始指标；比对切换目标前后历史；验证相同请求重试、无内容变化且无新增确认的保存及冲突请求 | 初始值分别为 2/1/1/1 和 1/1/0/0；已排期二面不计完成；历史归属不变；无重复事件或无效 revision 增长；未变更保存不撤销已有确认；旧 revision／同键不同参数均拒绝覆盖 |

浏览器或桌面控制不可用时，完成可执行的静态和纯逻辑验证，明确哪些视觉／交互未验证。不能仅以文件存在、脚本语法通过或截图生成宣称 A01–A12 全部通过。
