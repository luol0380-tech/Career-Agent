# Career Agent｜第三阶段任务包：入口集中与 PDF 简历

状态：accepted
负责人：Cursor 已实现；Codex 负责契约 Review 与关键节点复审。

## 目标

解决用户“找不到下一步、找不到上传入口、找不到修改位置”的问题。产品保留明确的页面操作，同时增加轻量的求职助手入口，不改成纯聊天产品。

## 本阶段范围

### 1. 首页主入口

在求职进展首页首屏提供三个明显动作：

- 上传 PDF 简历
- 查看／修改我的简历
- 开始整理求职材料

入口必须使用用户语言，不能隐藏在岗位详情或版本列表中。

### 2. 我的简历集中入口

新增“我的简历”入口，统一展示：

- 当前简历文件或材料名称
- 上传状态：待读取、待确认、已确认、读取失败
- 查看内容
- 修改内容
- 重新上传
- 历史材料版本

用户不需要先理解 Document、DocumentVersion 或其他实现概念。

### 3. PDF 上传演示能力

- 支持选择本地 PDF 文件。
- 记录文件名、大小、类型、读取状态和来源关联。
- 当前阶段可只保存原始文件元信息与用户粘贴／编辑的文本，不宣称已完成可靠 PDF 解析。
- 读取失败必须显示原因和重试入口。
- 新上传内容默认“待确认”，未经用户确认不得作为肯定职业事实。
- 不上传到云端，不调用真实 AI，不自动生成简历结论。

### 4. 轻量求职助手

- 首页提供一个“求职助手”入口。
- 首阶段只支持预设引导和跳转，例如“上传简历”“修改简历”“查看岗位”“记录面试”。
- 可以用对话式文案引导用户，但每个动作必须落到明确页面或按钮。
- 不实现开放式意图识别，不编造分析结论。

## 不在本阶段

- 完整聊天机器人、自由文本意图识别和多轮 Agent 编排。
- 可靠的 PDF 版式解析、OCR、云端文件存储。
- 自动生成简历、自动投递、自动修改用户事实。
- 重做现有岗位评估、资产确认和文档版本规则。

## 契约要求

- 实现前更新 `docs/DATA_SCHEMA.md`：定义 PDF 原始文件元信息、来源关联、读取状态和用户确认边界。
- 更新 `docs/STATE_EVENT_MODEL.md`：定义上传、读取失败、用户确认事件；事件必须可幂等重试。
- 明确旧数据缺少文件记录时的读取兼容规则。
- 文件选择失败、读取失败、取消选择和重复上传都要有可见状态。

## 用户验收重点

1. 首页首屏能看到上传 PDF 入口。
2. 上传后能明确看到文件名和当前状态。
3. 能从“我的简历”进入查看和修改，不需要从岗位详情反向寻找。
4. 上传失败时不会显示成功，也不会丢失上一份材料。
5. 用户确认前，页面不会把 PDF 内容显示成已确认事实。
6. 求职助手入口能把用户带到正确页面，但不伪装成完整 AI。

入口仍为 `app/index.html`，无需启动服务。
