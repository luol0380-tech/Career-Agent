# Career Agent｜第七阶段任务包：真实模型配置与可控验证

状态：ready_for_review
日期：2026-10-01
前置：第六阶段已 accepted

## 目标
先接入 DeepSeek 作为第一家模型提供方，把真实 AI 生成从“控制台临时配置”推进为清晰、可控的验证流程。用户可以看到当前是否已配置模型、发送范围、调用状态和费用／隐私提醒；没有配置时仍可使用本地演示建议，但不能伪装真实生成。

## DeepSeek 配置

- 官方兼容接口：`https://api.deepseek.com`，请求路径为 `/chat/completions`。
- 默认模型先使用 `deepseek-chat`；模型名必须可配置，不能散落在页面代码中。
- API Key 只允许由当前页面会话注入，不能提交到仓库、写入 localStorage、业务事件或截图。
- 参考官方文档：[DeepSeek API 文档](https://api-docs.deepseek.com/zh-cn/)。

## 必须完成

1. 增加清晰的模型配置状态区域：未配置、已配置待验证、验证成功、验证失败。
2. 不在业务 localStorage 中保存 API 密钥；配置只存在当前页面会话，刷新后默认清除，并提供清除配置动作。
3. 生成前再次展示发送范围、外发提醒、模型名称和当前验证状态；用户确认后才允许调用。
4. 调用过程显示准备中、请求中、成功、失败四种结果；超时、限额、权限错误和格式错误要给用户可理解的下一步。
5. 成功响应必须经过结构校验：每条建议引用简历原文，禁止新增未经依据的经历、数字和技能；不符合结构时按失败处理。
6. 成功结果继续进入现有逐条采纳／跳过／改写后采纳／保存新草稿流程。
7. 提供“本地演示建议”作为无密钥练习路径，明确标记不是真实 AI。
8. 不在日志、事件、截图、测试 fixture 或 HANDOFF 中写入真实密钥和完整简历正文。
9. 不修改既有契约字段和事件语义；若必须新增配置记录字段，先写 HANDOFF 的问题、影响、最小建议。

## 真实调用验证边界

- Cursor 可以用测试适配器覆盖成功、失败、超时和格式错误。
- 没有用户提供的模型配置时，不得发起外部请求，也不得写“真实调用通过”。
- 如果需要用户配置密钥，交付时只说明配置位置和清除方法，不要求用户把密钥发到聊天或提交到仓库。

## 验收重点

- 用户能看懂当前是否真的接入模型；
- 未配置时不会误导为生成成功；
- 配置清除后状态恢复未配置；
- 失败不会覆盖原简历或岗位草稿；
- 成功结果能进入现有检查与保存流程；
- 密钥不落盘、不出现在日志和截图；
- 完成后更新 HANDOFF 为 `ready_for_review`，如未做真实外部请求必须明确记录“真实调用未验证”。
