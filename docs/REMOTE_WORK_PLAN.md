# Career Agent｜明日远程协作与验收计划

日期：2026-09-30
适用阶段：第七阶段 DeepSeek 接入

## 工作原则

- Cursor 连续施工，Codex 在每个任务完成后独立复审。
- 每个完成功能都标记为“待用户亲测”，即使自动测试通过也不跳过用户验收。
- 用户不在线时不等待、不反复发消息；只记录进度、阻塞和待验收地址。
- 不启动项目服务，不提交密钥，不把真实简历或 API Key 写入仓库。

## 明日执行顺序

### 1. DeepSeek 接入准备（无需用户在线）

Cursor 完成：

- DeepSeek provider 适配；
- 默认接口与模型配置；
- 未配置、请求中、成功、失败、超时、限额状态；
- 发送范围确认；
- 清除当前会话配置；
- 密钥不落盘、不进日志；
- 测试适配器覆盖成功和失败。

用户回来后亲测：

- 页面能否看懂当前是否已配置；
- 未配置时是否没有假成功；
- 清除配置后是否恢复未配置；
- 发送范围是否清楚。

### 2. DeepSeek 真实请求验证（需要用户提供配置）

需要用户提供：

- 用户本人创建的 DeepSeek API Key；
- 默认使用 `deepseek-chat`，如需其他模型需提前指定。

提供方式：

- 不要把 Key 发到聊天；
- 不要提交到仓库；
- 只在本机当前页面会话中临时设置；
- 验证结束后立即清除。

如果用户没有提供 Key：

- Cursor 继续完成模拟适配器和失败路径；
- Codex 可以完成代码 Review；
- 真实调用标记“未验证”，不会阻塞其他开发。

### 3. 真实结果安全检查（需要用户回来）

用户亲测：

- 发送前展示了哪些内容；
- 返回建议是否引用简历原文；
- 是否出现编造经历、公司、数字或技能；
- 采纳建议是否只生成新草稿；
- 原简历是否保持不变；
- 失败重试是否保留原内容。

### 4. 验收记录

每个功能完成后，交付记录必须包含：

- 浏览地址；
- 功能说明；
- 自动测试结果；
- 用户待亲测项目；
- 是否需要 API；
- 是否需要后端；
- 未验证限制。

## 需要用户回来处理的事项

1. 亲自验收每个新功能，不要求一次完成，可以逐项记录。
2. 决定是否提供 DeepSeek API Key 进行真实调用验证。
3. 确认是否允许简历正文发送到外部模型服务。
4. 判断生成建议是否符合你的求职场景和语气。
5. 发现问题时提供截图或描述，不需要分析代码。

## 当前不需要用户提供的事项

- 不需要立刻提供后端服务器；
- 不需要立即注册云端数据库；
- 不需要把简历文件发给 Codex 或 Cursor；
- 不需要在线等待每个施工步骤；
- 不需要手动转述项目背景。

## 需要后端的时点

当前演示仍可在浏览器本地完成。只有进入正式版本，才需要后端处理：

- API Key 保护；
- 用户账号和权限；
- 简历云端存储与删除；
- 模型请求代理；
- 用量和费用统计；
- 审计与隐私控制。

没有后端时，浏览器直连模型只适合作为临时验证，不作为正式上线方案。
