# Career Agent｜Review Gate 审查闸门

## 触发条件

只有 `docs/HANDOFF.md` 出现新的 `ready_for_review`，或用户明确要求复审时，才能启动本闸门。

## 必查项目

### 1. 范围

- 当前任务包状态和阶段一致；
- 实际改动没有扩大任务范围；
- 未擅自修改契约、状态枚举或事件语义；
- 不在范围的能力已明确写出。

### 2. 实现

- 页面入口真实可达；
- 成功、失败、取消、重试路径都可理解；
- 原有数据不会被错误覆盖；
- 写入经过统一业务操作入口；
- 用户文案表达结果、影响和下一步，不暴露实现术语。

### 3. 安全与事实

- 合成数据与真实数据边界明确；
- AI 衍生内容没有被显示成用户事实；
- API Key、简历正文和敏感信息不进入仓库、日志、截图或 localStorage；
- 外部模型调用是否真实发生必须如实记录。

### 4. 验证

- 独立运行逻辑测试；
- 独立运行浏览器测试；
- 记录实际通过数和失败数；
- 测试失败或未运行时不得写“通过”；
- 测试适配器通过不等于真实外部调用通过。

### 5. 用户验收

- 提供可打开的浏览地址；
- 每个新增功能都有逐步操作和预期结果；
- 标记“待用户亲测”的项目；
- 明确需要用户提供的 API、授权或产品决策。

## 审查结论

- `accepted`：必查项目均有证据，且无阻塞问题。
- `changes_requested`：存在可修复问题，必须列出文件、现象、影响和最小修复建议。
- `blocked`：同一外部阻塞条件连续出现至少三次，且没有不依赖该条件的工作可继续；必须说明需要谁提供什么。

## 自动化检查边界

自动检查只负责发现 HANDOFF 状态变化并提醒；它不能替代代码 Review、测试复跑或用户亲测。Codex 必须读取实际文件并独立验证后，才能更新 Review 结论。
